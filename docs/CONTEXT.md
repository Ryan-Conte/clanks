# Context and memory

This doc covers what each clank knows when it starts work, where that knowledge comes from, and who can change it. Two layers matter most. Every **project** has a shared context that all the clanks working on it can read and add to. Every **clank** has its own memory of its own work in that project, which only it reads.

This is the full spec. The summary is in the [buildout plan](PLAN.md#context-and-memory).

## Layers

A clank's prompt is built from these layers, in this order. Stable layers come first, so prompt caching works across turns and runs.

| Layer | Scope | Written by | Holds |
| --- | --- | --- | --- |
| Crew rules and priming doc | Every project | Bundled, or your edited copy | How this clank works ([crew/](../crew/README.md)) |
| Integration guides | Per project, per clank | Integration authors | How to use the services connected for this clank |
| Your profile | All your projects | You | Your name, time zone, language, preferences, writing samples |
| Project instructions | One project: everyone, plus a section per clank | You | `CLANKS.md` |
| **Project context** | One project, **all clanks** | You and the crew | Project facts, brief, spec summary, design language, project notes |
| **Clank memory** | One project, **one clank** | That clank (you can edit it) | Its chats, run summaries, and its decisions with their reasons |
| Run context | One run | The app | The ticket or conversation |

**Instructions and information are kept apart.** The priming docs, your profile, `CLANKS.md` and the ticket are instructions. Project notes, memory, the spec, research and everything read through tools are information. Clanks are told so in the prompt, and nothing a clank writes can become an instruction.

## Your profile

Settings → Profile holds what every clank in every project should know about you: your name, time zone, language and spelling ("Australian English"), how you like replies, things never to do, and optional writing samples for Quill and Buzz. It's kept under 300 tokens.

## Project instructions: CLANKS.md

`CLANKS.md` lives at the root of the project's workspace (repo or folder), so it's versioned with the work. You write it. The top part applies to every clank. A section headed `## For <clank>` applies only to that clank, and each clank gets the top part plus its own section. If there's no `CLANKS.md`, `AGENTS.md` is used.

```markdown
# Surf shop

We sell surfboards in Australia only. Prices include GST. Write in Australian English.

## For Forge

Use pnpm. Run `pnpm test` and `pnpm lint` before submitting. Never touch `legacy/`.

## For Buzz

Our voice is relaxed and local. At most one emoji per post.
```

It can be edited in the Context tab or in any editor, and is picked up at the next run. A clank's change to `CLANKS.md` in its own worktree is flagged in review and takes effect only once you merge it.

## Project context

The crew's shared knowledge for one project, readable by every clank in it.

### What's in it

- **Project facts.** Generated by the app and read-only: the repo and base branch, how to build and run the project (detected or set by you), connected integrations and whether each is in test or live mode, the crew and their models, the current spec version and active routines. Always included.
- **Brief and spec.** The project brief and a summary of the approved spec: story ids and titles. Clanks read the full spec with `spec_read`.
- **Design language.** When the project has one, a summary of `design/DESIGN.md` and the token names.
- **Project notes.** The shared knowledge base, described below.

### Project notes

Each note has a kind, a title, a body, why it's true or was decided, its author (a clank or you), the ticket it came from, a status, and whether it's pinned.

| Kind | Example |
| --- | --- |
| `fact` | Prices include 10% GST. |
| `decision` | Cart state lives in Zustand, because the storefront and the quiz share it. (Forge, CLK-103) |
| `convention` | Product URLs are kebab-case: `/boards/fish-6-2`. |
| `glossary` | "Board finder" is the quiz. Never "the survey". |
| `link` | Stripe test dashboard: https://dashboard.stripe.com/test |

**Writing notes**

- You add, edit, pin and delete notes in the Context tab.
- Clanks add notes with `context_write` when they learn or decide something other clanks will need.
- A clank's note starts **provisional**. The rest of the crew sees it straight away, marked as provisional, so parallel work can use it. It becomes **active** when the ticket it came from is approved. Atlas can fix or drop it at sign-off, and you can at any time. A rejected ticket's provisional notes are dropped.
- A new note can supersede an old one. The old note stays in history, marked superseded, and is no longer included in prompts.
- Notes are information, not instructions, and are labelled that way in prompts. A note can't change permissions, tools or the workflow.
- `context_write` rejects anything that looks like a secret, using the same scan as marketplace publishing.
- Every new note appears in the board's activity feed: "Forge › noted for the crew: cart state lives in Zustand".

**Reading notes**

- Always included: project facts and pinned notes.
- Then, by relevance: notes that match the ticket's title, stories and type (SQLite FTS5), within the layer's budget.
- `context_search` finds more, across notes, the spec, the design language and `CLANKS.md`.

**Keeping it tidy**

- At sign-off, Atlas merges duplicates and supersedes stale notes.
- A built-in "tidy project notes" routine can do a full pass every month. It's off by default.
- The Context tab lists notes no clank has used in 60 days.

## Clank memory

Each clank's own memory in each project:

- its chats with you;
- a summary of every run it did;
- the decisions it recorded with `memory_write`, with their reasons.

Other clanks can't read it. The exception is Atlas, which can search the memory of a clank whose ticket it is signing off. You can read, edit and delete any entry under the clank's profile → Memory. Ask Forge why it picked a library and it answers from this record, or says it has none.

## What goes where

| Put it in | When |
| --- | --- |
| Project context | Other clanks need it: facts, decisions that affect others' work, conventions, names |
| Clank memory | It's about this clank's own work and reasoning: why Forge took this approach on CLK-104 |
| `CLANKS.md` | It's an instruction you want followed. Only you write it. |
| The spec | It's what the product must do. Scribe writes it, you approve it. |

## Budgets

Each layer has a token budget, scaled to the model's context window. Defaults for a 32k-token model:

| Layer | Budget |
| --- | --- |
| Crew rules and priming doc | Up to 2,500 |
| Integration guides | 300 each |
| Your profile | 300 |
| `CLANKS.md` (top part and this clank's section) | 1,500 |
| Project context | 2,000 |
| Clank memory | 1,000 |
| Run context | The rest, keeping room for tool results and the reply |

On a 16k-token model, project context and clank memory get half. If `CLANKS.md` or the pinned notes don't fit, the Context tab tells you rather than silently cutting them.

## Seeing what a clank sees

Context tab → **Preview**: pick a clank and a ticket to see the assembled prompt layer by layer, with token counts. The same view opens from any run in its activity timeline, so you can answer "what did it know when it did that?". When a clank runs on a cloud model, the preview also shows that this is what gets sent to the provider.

## Tools

| Tool | Who | What |
| --- | --- | --- |
| `context_search` | Every clank | Search the project context |
| `context_write` | Every clank | Add a project note, or update or supersede one. Atlas can also drop notes. |
| `memory_search` | Every clank | Search its own memory |
| `memory_write` | Every clank | Record a decision and its reason in its own memory |

## Data model

- **user_profile**: name, time zone, language, preferences, writing samples.
- **context_note**: id, project, kind (`fact`, `decision`, `convention`, `glossary`, `link`), title, body, why, author (clank or user), ticket, status (`provisional`, `active`, `superseded`, `dropped`), supersedes, pinned, last used, created, updated. Indexed with FTS5.
- **memory**: id, project, clank, kind (`decision`, `note`, `run_summary`), body, ticket, run, created. Indexed with FTS5.
- Project facts are computed when a prompt is built, not stored.

## Security and privacy

- Only you write instructions: your profile, `CLANKS.md` and the priming docs. Everything a clank writes is information.
- Provisional notes are labelled in prompts and in the UI until their ticket is approved.
- A clank can only read the context of the project it's working in. Marketplace clanks get the same layers and nothing more.
- Context stays on your machine. It's sent to a cloud provider only as part of the prompt for a clank you've put on a cloud model, and the Preview shows exactly what that is.

## Testing

- Prompt assembly: layer order, budgets, scaling to the context window, and per-clank `CLANKS.md` sections.
- The note lifecycle: provisional, active, superseded and dropped, and secret rejection.
- Retrieval on fixture projects: the right notes and memories come back for a ticket.
- Isolation: no clank sees another project's context or another clank's memory (except Atlas at sign-off).

## Open questions
